    8. Authentication and Authorization

    Two distinct questions arise for each request:

    • Who is the user? This is authentication: the user has identified themselves with a username and password, and every subsequent request must prove that it comes from them;
    • Do they have permission to access this page? This is authorization: in the case study, only a user with the role ADMIN manages doctors and clients.

    Identity proof must be included with every request. [Symfony] typically stores the logged-in user in its session (see the section on scopes), which is the simplest solution for a web application. The case study, in all its versions ([ASP.NET Core MVC], [Spring MVC], [NestJS], [Flask], [Laravel]), instead uses a token (JWT, JSON Web Token), which we will use here: After login, the server generates a token containing the user’s identity and signs it with a secret key (this is the principle behind the signed cookie in Example 23). The token is stored in a cookie; the browser sends it back with every request; the server verifies the signature. The user can read their token but cannot modify it: any modification invalidates the signature. The format is standardized (RFC 7519), understood by all programming languages, and the token includes its expiration date. Most importantly, the server doesn’t need to store anything: any server that knows the key can verify the token.

    [Symfony] has a comprehensive security component, integrated by SecurityBundle, whose elements we will use as-is:

    • the application’s URL are distributed across firewalls (firewalls), each with its own method of authenticating users;
    • authentication is handled by authenticators (authenticators): objects that determine the user’s identity for each request. [Symfony] provides several of these (login form, session, API token, etc.); we will write our own, which reads the JWT token. The rest of the application sees only the result: the authenticated user, provided by [#[CurrentUser]], [$this->getUser()], and, in the views, [app.user];
    • users are provided by a user provider, and their passwords are hashed by the PasswordHasher component (algorithm [bcrypt]);
    • authorizations are role-based: page protection is described by access control rules ([access_control]) or by the [#[IsGranted]] attribute of actions; views check for a right using [is_granted];
    • Login attempts are limited by the RateLimiter component (Example 27).

    All of this is accomplished by kernel event listeners (previous chapter): the firewall listens for [kernel.request] (priority 8), [#[IsGranted]] is read on [kernel.controller_arguments], and access denials are exceptions, handled on [kernel.exception].

    Token generation and verification are handled by the [firebase/php-jwt] library, the most commonly used one in [PHP], installed by the [composer.json] file from the examples. (There is a widely used bundle for tokens—JWT and [LexikJWTAuthenticationBundle]—designed for API; for a web application, just a few lines are sufficient, and they better illustrate the mechanism.)

The hash is generated using the bcrypt algorithm, designed for passwords. It has two distinctive features. It is intentionally slow, with an adjustable level of slowness (the cost, here set to 10: 2^10 computational cycles, resulting in the hash [$10$]): a few tens of milliseconds, imperceptible to a user, but which make it very costly for a hacker to try billions of passwords. It is salted: a randomly generated salt is mixed with the password before hashing and stored within the hash itself (the 22 characters following [$10$]); thus, two users with the same password will have different hashes. The hashes were calculated once and for all by the function [password_hash] from [PHP] (line 16), or by the command [bin/console security:hash-password] from [Symfony]: Calculating them with every request would be an unnecessary waste of time, since the application is rebuilt with every request. [bcrypt] only takes into account the first 72 bytes of a password: the case study accounts for this;

    <?php
// src/Securite/AuthService.php: password verification and tokens JWT

namespace App\Securite;

use Firebase\JWT\JWT;
use Firebase\JWT\Key;
use Symfony\Component\DependencyInjection\Attribute\Autowire;
use Symfony\Component\PasswordHasher\Hasher\UserPasswordHasherInterface;
use Throwable;

class AuthService
{
     // the name of the cookie that carries the token
    public const COOKIE = 'jeton';

    public function __construct(
        private UtilisateursService $utilisateurs,
         // the password hashing service (see config/packages/security.yaml)
        private UserPasswordHasherInterface $hacheur,
         // #[Autowire(env: ...)]: the value of an environment variable (.env file);
         // the "int" prefix: converts it to an integer
         #[Autowire(env: 'JWT_SECRET')] private string $secret,
         #[Autowire(env: 'int:JWT_DUREE_MINUTES')] public readonly int $dureeMinutes,
    ) {
    }

     // the user, or null if the login is unknown or the password is incorrect.
     // isPasswordValid hashes the entered password with the stored hash salt,
     // then compares the two results
    public function valider(?string $login, ?string $motDePasse): ?Utilisateur
    {
        if (! $login || $motDePasse === null) {
            return null;
        }
        $utilisateur = $this->utilisateurs->chercher($login);
        if ($utilisateur === null || ! $this->hacheur->isPasswordValid($utilisateur, $motDePasse)) {
            return null;
        }
        return $utilisateur;
    }

     // the user’s token (JWT), signed with the secret key (HMAC-SHA256)
    public function creerJeton(Utilisateur $utilisateur): string
    {
        $maintenant = time();
         // the token’s content: the “claims” (statements about the user)
        $claims = [
            'sub' => $utilisateur->login,
            'nom' => $utilisateur->nom,
            'role' => $utilisateur->role,
            'iat' => $maintenant,
            'exp' => $maintenant + $this->dureeMinutes * 60,
        ];
        return JWT::encode($claims, $this->secret, 'HS256');
    }

     // the user described by a token whose signature and expiration date
     // are valid; null otherwise (token is forged, expired, or unreadable)
    public function verifier(string $jeton): ?Utilisateur
    {
        try {
             // decode returns an object; (array) converts it to an associative array
            $claims = (array) JWT::decode($jeton, new Key($this->secret, 'HS256'));
        } catch (Throwable) {
            return null;
        }
        return new Utilisateur($claims['sub'], $claims['nom'], $claims['role'], claims: $claims);
    }
}

The lifetime is a read-only public property: the controller will use it;
    • lines 31–41: verification of a username and password. [isPasswordValid] hashes the entered password using the stored hash salt and compares the two hashes. An unknown username and an incorrect password yield the same result, [null];
    • Lines 44–56: Token generation. The token contains an array of statements (claims) about the user. Some have standardized names: [sub] (subject), the user ID; [iat] (issued at), the creation date; [exp] (expiration), the expiration date. Dates are expressed in seconds elapsed since January 1, 1970 (the function [time()] of [PHP]). The other fields are optional: here, the name and role. [JWT::encode] generates the token and signs it using the algorithm [HS256] (HMAC-SHA256, a signature using a shared secret key);
    • lines 60–69: token verification. [JWT::decode] verifies the signature and expiration date, then returns the assertions (an object, converted to an array by [(array)]). Any anomaly (forged, expired, or malformed token) raises an exception; [catch (Throwable)] catches them all ([Throwable] is the interface for all exceptions and errors from [PHP]; the variable name is optional when not used). The [Key] object associates the key with an algorithm: a token that specifies a different algorithm (or none at all, [none]) would be rejected. The valid token becomes a [Utilisateur], without a hash, along with its claims (parameter named [claims]).

// src/Securite/JetonAuthenticator.php: the AUTHENTIFICATEUR of the firewall (see
// config/packages/security.yaml): for each request, it determines who the user is,
// based on the JWT token in the [jeton] cookie

namespace App\Securite;

use Symfony\Component\HttpFoundation\RedirectResponse;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\Security\Core\Authentication\Token\TokenInterface;
use Symfony\Component\Security\Core\Exception\AuthenticationException;
use Symfony\Component\Security\Core\Exception\CustomUserMessageAuthenticationException;
use Symfony\Component\Security\Http\Authenticator\AbstractAuthenticator;
use Symfony\Component\Security\Http\Authenticator\Passport\Badge\UserBadge;
use Symfony\Component\Security\Http\Authenticator\Passport\Passport;
use Symfony\Component\Security\Http\Authenticator\Passport\SelfValidatingPassport;
use Symfony\Component\Security\Http\EntryPoint\AuthenticationEntryPointInterface;

class JetonAuthenticator extends AbstractAuthenticator implements AuthenticationEntryPointInterface
{
    public function __construct(private AuthService $auth)
    {
    }

     // the authenticator only acts if the request includes the token cookie;
     // otherwise, the visitor remains anonymous
    public function supports(Request $request): ?bool
    {
        return $request->cookies->has(AuthService::COOKIE);
    }

     // the user’s PASSEPORT: who they are (the badge), and how to verify it.
     // The token has already been verified: the passport validates itself (SelfValidatingPassport)
    public function authenticate(Request $request): Passport
    {
        $utilisateur = $this->auth->verifier($request->cookies->get(AuthService::COOKIE));
        if ($utilisateur === null) {
            throw new CustomUserMessageAuthenticationException('jeton invalide');
        }
         // The badge: the login, and a function that identifies the user (in this case, the one with the
         // token, without consulting the user list)
        return new SelfValidatingPassport(new UserBadge($utilisateur->login, fn () => $utilisateur));
    }

     // a valid token: null; the request proceeds to the action
    public function onAuthenticationSuccess(Request $request, TokenInterface $token, string $firewallName): ?Response
    {
        return null;
    }

     // an invalid token (expired, forged): redirects to /login, and the cookie is cleared
    public function onAuthenticationFailure(Request $request, AuthenticationException $exception): ?Response
    {
        $reponse = new RedirectResponse('/login');
        $reponse->headers->clearCookie(AuthService::COOKIE);
        return $reponse;
    }

     // POINT from ENTRÉE: the response sent to an anonymous visitor requesting a
     // a protected page; in this case, a redirect to the login page
    public function start(Request $request, ?AuthenticationException $authException = null): Response
    {
        return new RedirectResponse('/login');
    }
}

    For each request that passes through the firewall, [Symfony] calls the authenticator’s methods in this order:

    • lines 28–31: [supports]: Is the authenticator involved in this request? Yes, if it contains the token cookie. Otherwise, nothing happens: the visitor remains anonymous;
    • lines 35–44: [authenticate] constructs a passport: the user’s identity (a badge, [UserBadge]), and the credentials to be verified. A standard login form would include the entered password in the passport, which [Symfony] would verify itself. Here, the proof is the token, already verified by [AuthService]: the passport validates itself ([SelfValidatingPassport]).     public function connexion(Request $request): Response
    {
         // the form’s anti-CSRF token (see Example 21)
        if (! $this->isCsrfTokenValid('login', $request->getPayload()->getString('_csrf_token'))) {
            throw new AccessDeniedHttpException('jeton anti-CSRF invalide');
        }
        $login = $request->getPayload()->getString('login');
        $utilisateur = $this->auth->valider($login, $request->getPayload()->getString('motDePasse'));
        if ($utilisateur === null) {
             // a deliberately vague message: it does not specify whether it is the username or the password
            return $this->render('auth/login.html.twig', ['login' => $login,
                'erreur' => 'Login ou mot de passe incorrect.']);
        }

         // (httpOnly); it does not accompany POST requests coming from other sites
         // (sameSite); it disappears when the token expires
        $reponse = $this->redirect('/profil');

            ->withHttpOnly(true)
            ->withSameSite(Cookie::SAMESITE_LAX));
        return $reponse;
    }

     // cannot log the user out without their knowledge); the cookie is deleted
     #[Route('/logout', methods: ['POST'])]
    public function deconnexion(Request $request): Response
    {
        if (! $this->isCsrfTokenValid('logout', $request->getPayload()->getString('_csrf_token'))) {
            throw new AccessDeniedHttpException('jeton anti-CSRF invalide');
        }
        $reponse = $this->redirect('/login');
        $reponse->headers->clearCookie(AuthService::COOKIE);
        return $reponse;
    }

     // a few dark colors, clearly legible against the light background
    private const COULEURS = ['#1f4e79', '#7b2d26', '#2e6b30', '#5b2c83', '#8a5a00', '#23395d', '#9c2a5b'];

     // random text. random_int is a "cryptographic" generator,
     // unpredictable (unlike rand or mt_rand, whose sequence could be guessed)
    public static function texteAleatoire(int $longueur): string
    {
        $alphabet = array_keys(self::POLICE);
        $texte = '';
        for ($i = 0; $i < $longueur; $i++) {
            $texte .= $alphabet[random_int(0, count($alphabet) - 1)];
        }
        return $texte;
    }

     // a random decimal number between $minimum and $maximum
    private static function hasard(float $minimum, float $maximum): float
    {
        return $minimum + ($maximum - $minimum) * random_int(0, PHP_INT_MAX) / PHP_INT_MAX;
    }

    private static function couleur(): string
    {
        return self::COULEURS[random_int(0, count(self::COULEURS) - 1)];
    }

    public static function svg(string $texte): string
    {
        $l = self::LARGEUR;
        $h = self::HAUTEUR;
        $morceaux = ["<svg xmlns=\"http://www.w3.org/2000/svg\" width=\"$l\" height=\"$h\" viewBox=\"0 0 $l $h\">",
             '<rect width="100%" height="100%" fill="#f5f7fa"/>'];

         // the characters: each enlarged, tilted, and offset, and each dot
         // slightly shifted at random
        $pas = ($l - 20) / strlen($texte);
        foreach (str_split($texte) as $i => $caractere) {
            $echelle = self::hasard(4.6, 5.6);    // one grid unit in pixels
            $angle = self::hasard(-0.35, 0.35);   // rotation, in radians (approximately ±20°)
            $cx = 10 + $pas * ($i + 0.5) + self::hasard(-3, 3);    // center of the character
            $cy = $h / 2 + self::hasard(-4, 4);
            foreach (self::POLICE[$caractere] as $trait) {
                $d = [];
                for ($k = 0; $k < count($trait); $k += 2) {
                     // grid point, centered at (2, 3), distorted, rotated, positioned
                    $x = ($trait[$k] - 2 + self::hasard(-0.2, 0.2)) * $echelle;
                    $y = ($trait[$k + 1] - 3 + self::hasard(-0.2, 0.2)) * $echelle;
                    $px = $cx + $x * cos($angle) - $y * sin($angle);
                    $py = $cy + $x * sin($angle) + $y * cos($angle);
                    $d[] = sprintf('%s%.1f %.1f', $k === 0 ? 'M' : 'L', $px, $py);
                }
                $morceaux[] = sprintf('<path d="%s" fill="none" stroke="%s" stroke-width="%.1f" '
                    .'stroke-linecap="round" stroke-linejoin="round"/>',
                    implode(' ', $d), self::couleur(), self::hasard(2.2, 3));
            }
        }

         // 3 scrambling lines: curves that cross the image
        for ($n = 0; $n < 3; $n++) {
            $morceaux[] = sprintf('<path d="M%.1f %.1f C%.1f %.1f %.1f %.1f %.1f %.1f" fill="none" '
                .'stroke="%s" stroke-width="1.3"/>',
                self::hasard(0, 20), self::hasard(5, 45), self::hasard(30, 60), self::hasard(0, 50),
                self::hasard(90, 120), self::hasard(0, 50), self::hasard(130, 150), self::hasard(5, 45),
                self::couleur());
        }
        $morceaux[] = '</svg>';
        return implode('', $morceaux);
    }
}

    The image is in the SVG format (Scalable Vector Graphics): a vector drawing described in XML—that is, text—which the server generates without a graphics library, and which the browser displays directly on the page. This class is pure [PHP], with nothing specific to a framework: it is the same as the [Laravel] version of this course.

    • Lines 16–49: a minimalist “font”: each character is a list of strokes, and each stroke is a list of [x, y] coordinates in a 4 × 6 grid. Characters that are easily confused ([0] and [O], [1], [I], and [L]) are excluded;
    • Lines 56–64: a random string selected from the characters in the font ([array_keys], the keys in the table). The functions [rand] and [mt_rand] of [PHP] produce predictable number sequences (anyone who knows a few values can guess the next ones): they are suitable for simulations, not for security.     • lines 67–70: a random floating-point number, generated from a random integer ([PHP_INT_MAX] is the largest integer in [PHP]);

Each character is randomly scaled, rotated, and moved, and each of its points is slightly offset; each line becomes an element [<path>] of the SVG ([M]: displacement, [L]: line). // src/Security/CaptchaService.php: pending CAPTCHAs, stored by the server,
// in the cache (see example 20)

namespace App\Securite;

use Psr\Cache\CacheItemPoolInterface;

class CaptchaService
{
     // the lifespan of a CAPTCHA, in seconds
    private const DUREE_VIE = 600;

    public function __construct(private CacheItemPoolInterface $cache)
    {
    }

    public function generer(): Captcha
    {
        $texte = DessinCaptcha::texteAleatoire(5);
         // a random identifier, impossible to guess: 12 bytes generated by a
         // cryptographic generator (random_bytes), written in hexadecimal (bin2hex)
        $id = bin2hex(random_bytes(12));
         // the expected response, cached for 10 minutes (expiresAfter): the
         // the cache will eventually forget it on its own
        $element = $this->cache->getItem("captcha.$id");
        $this->cache->save($element->set($texte)->expiresAfter(self::DUREE_VIE));
        return new Captcha($id, DessinCaptcha::svg($texte));
    }

     // the CAPTCHA is CONSOMMÉ in all cases: an image is used only once
    public function verifier(?string $id, ?string $saisie): bool
    {
         // an invalid identifier cannot be a cache key
        if ($id === null || ! ctype_xdigit($id) || $saisie === null) {
            return false;
        }
        $element = $this->cache->getItem("captcha.$id");
         // deleteItem: the response is removed from the cache, whether it is correct or not
        $this->cache->deleteItem("captcha.$id");
        if (! $element->isHit()) {
            return false;    // Unknown identifier, or expired CAPTCHA
        }
         // strcasecmp returns 0 for two equal strings, case-insensitive
        return strcasecmp($element->get(), trim($saisie)) === 0;
    }
}
    • Lines 18–29: a new CAPTCHA: random text, a random and unguessable identifier, and the image. For each identifier, the server stores the expected response in the cache (example 20) for ten minutes: the [expiresAfter] method of the cache element sets its lifetime in seconds. After this time, the cache automatically discards it. The page receives only the identifier and the image: the response never leaves the server;
    • lines 32–46: the validation. The identifier comes from the client: we first verify that it consists of hexadecimal digits ([ctype_xdigit]), since certain characters ([{}()/\@:]) are prohibited in cache keys, which would throw an exception. The element is read, then removed from the cache ([deleteItem]): the CAPTCHA is consumed in all cases, whether successful or not. Without this, a program could try all possible answers on the same image. The comparison ignores case ([strcasecmp] returns 0 for two equal strings, regardless of uppercase or lowercase letters) and spaces around the input ([trim]).

A rate limiter distributes “tokens” (unrelated to the token JWT): each restricted action consumes one, and when there are no more left, the action is denied. // src/Controller/AuthController.php: login (with CAPTCHA and a limit of

namespace App\Controller;

use App\Securite\AuthService;
use App\Securite\CaptchaService;
use Symfony\Bundle\FrameworkBundle\Controller\AbstractController;
use Symfony\Component\HttpFoundation\Cookie;
use Symfony\Component\HttpFoundation\Request;
use Symfony\Component\HttpFoundation\Response;
use Symfony\Component\HttpKernel\Exception\AccessDeniedHttpException;
use Symfony\Component\RateLimiter\RateLimiterFactoryInterface;
use Symfony\Component\Routing\Attribute\Route;

class AuthController extends AbstractController
{
     // $loginLimiter: the limiter factory [login] (see config/packages/framework.yaml);
     // the parameter name identifies the limiter
    public function __construct(
        private AuthService $auth,
        private CaptchaService $captchas,
        private RateLimiterFactoryInterface $loginLimiter,
    ) {
    }

     #[Route('/', methods: ['GET'])]
    public function accueil(): Response
    {
        return $this->redirect('/profil');
    }

     #[Route('/login', methods: ['GET'])]
    public function formulaire(): Response
    {
        return $this->pageLogin();
    }

     #[Route('/login', methods: ['POST'])]
    public function connexion(Request $request): Response
    {
        $saisies = $request->getPayload();
        if (! $this->isCsrfTokenValid('login', $saisies->getString('_csrf_token'))) {
            throw new AccessDeniedHttpException('jeton anti-CSRF invalide');
        }
        $login = $saisies->getString('login');
         // the client limiter: its failure counter uses its address as the key CE
        $limiteur = $this->loginLimiter->create($request->getClientIp());

         // 1. A blocked address isn't even listened to; `consume(0)` consults the
         // the counter without consuming any resources
        $etat = $limiteur->consume(0);
        if ($etat->getRemainingTokens() === 0) {
            $secondes = $etat->getRetryAfter()->getTimestamp() - time();
            return $this->pageLogin($login, "Trop de tentatives : réessayez dans $secondes s.");
        }
         // 2. First the CAPTCHA (low-cost), then the password (bcrypt, high-cost);
         // consume(0): another failure
        if (! $this->captchas->verifier($saisies->getString('captchaId'), $saisies->getString('captcha'))) {
            $limiteur->consume();
            return $this->pageLogin($login, "Le code de l'image est incorrect.");
        }
        $utilisateur = $this->auth->valider($login, $saisies->getString('motDePasse'));
        if ($utilisateur === null) {
            $limiteur->consume();
            return $this->pageLogin($login, 'Login ou mot de passe incorrect.');
        }
         // A successful login clears the failures
        $limiteur->reset();
        $reponse = $this->redirect('/profil');
        $reponse->headers->setCookie(Cookie::create(AuthService::COOKIE, $this->auth->creerJeton($utilisateur))
            ->withExpires(time() + $this->auth->dureeMinutes * 60)
            ->withHttpOnly(true)
            ->withSameSite(Cookie::SAMESITE_LAX));
        return $reponse;
    }

     #[Route('/logout', methods: ['POST'])]
    public function deconnexion(Request $request): Response
    {
        if (! $this->isCsrfTokenValid('logout', $request->getPayload()->getString('_csrf_token'))) {
            throw new AccessDeniedHttpException('jeton anti-CSRF invalide');
        }
        $reponse = $this->redirect('/login');
        $reponse->headers->clearCookie(AuthService::COOKIE);
        return $reponse;
    }

     // Each time the form is displayed, a NOUVEAU CAPTCHA is generated
    private function pageLogin(?string $login = null, ?string $erreur = null): Response
    {
        return $this->render('auth/login.html.twig', ['login' => $login, 'erreur' => $erreur,
            'captcha' => $this->captchas->generer()]);
    }
}
    • lines 21–26: the controller receives the factory for the limiter [login];
    • line 49: this client’s limiter, [create(clé)], returns a limiter that has its own counter under this key—in this case, the client’s address IP ([getClientIp()]);
    • lines 53–57: A blocked address is not even listened to. [consume(0)] queries the limiter without consuming anything; the [RateLimit] object it returns provides the number of remaining tokens ([getRemainingTokens()]) and the date when the action will be permitted again ([getRetryAfter()]), from which we can deduce the number of seconds to wait;
    • Lines 60–68: The CAPTCHA is verified before the password; verifying it costs almost nothing, whereas [bcrypt] is intentionally slow. A program that enters the wrong CAPTCHA would therefore not trigger [bcrypt]. Each failure—whether for the CAPTCHA or the password—consumes a token ([consume()], which consumes one by default). After the third failure, no tokens remain: the address is blocked until the end of the 60-second window, counted from the first failure;
    • line 70: a successful login clears the failed attempts ([reset()]);
    • lines 91–95: Each time the form is displayed, a new CAPTCHA is generated, even after a failed attempt.

    SecurityBundle also provides a built-in connection limit (the [login_throttling] firewall option), which applies to its own login authenticators ([form_login]...), not to our action. To limit the number of requests for a route, we would use a limiter in the same way, either within the action or in a listener for [kernel.request]. We chose to count only the failed attempts, so as not to inconvenience a user who is logging in normally.
